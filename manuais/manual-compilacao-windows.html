1. Visão geral

Este documento ensina a compilar o código-fonte do fork WMK Studio no Windows. O aplicativo é um workspace Rust com pacote principal figcraft, interface baseada em egui e renderização gráfica via wgpu. A compilação local é diferente de executar um pacote binário já publicado.

Estado verificado nesta máquina: Rust 1.95.0 MSVC, compilador Visual Studio e Windows SDK funcionaram; o Cargo chegou a compilar o pacote figcraft v0.15.0. Até a última conferência anterior à criação deste manual, o executável final não havia sido confirmado e a execução do aplicativo não tinha sido testada. Não trate a compilação como concluída sem a mensagem de sucesso.

Fluxo: Git → dependências Rust → compilação → linkedição → executável → testes → distribuição.

3. Preparar o ambiente

3.1. Obter o código

cd /d D:\Ferramentas
git clone https://github.com/WalneyNF/WMK-Studio.git
cd figcraft
git status
git rev-parse HEAD

Se a pasta já existir, não faça clone sobre ela. Confirme as alterações locais com git status antes de atualizar. Evite git reset --hard ou git clean -fdx sem backup e autorização.

3.2. Instalar o toolchain correto

rustup toolchain install 1.95.0-x86_64-pc-windows-msvc --profile minimal
rustup run 1.95.0-x86_64-pc-windows-msvc rustc --version
cargo --version

Instale Visual Studio ou Build Tools com o workload Desenvolvimento para desktop com C++ e um Windows SDK. A localização de instalação pode variar.

3.3. Ativar MSVC no terminal

Exemplo verificado nesta máquina; não é um caminho universal:

call "D:\one\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"
where cl
where link
echo %WindowsSdkDir%
echo %WindowsSDKVersion%

Se a instalação for diferente, descubra o caminho com vswhere.exe (normalmente na pasta Microsoft Visual Studio Installer) ou procure o arquivo VC\Auxiliary\Build\vcvars64.bat no Visual Studio instalado. Abra um novo terminal CMD após mudanças em PATH.

4. Compilar o fork

4.1. Método simples desta instalação

Dois scripts foram criados na raiz local do fork:

cd /d D:\Ferramentas\figcraft
wmk-ambiente.cmd
wmk-compilar.cmd

wmk-ambiente.cmd verifica MSVC/SDK/Rust; wmk-compilar.cmd carrega o MSVC e executa o Cargo. Os scripts atuais contêm o caminho local do Visual Studio e precisam ser adaptados antes de distribuí-los para outros computadores.

4.2. Método manual, independente dos scripts

cd /d D:\Ferramentas\figcraft
call "D:\one\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"
cargo +1.95.0-x86_64-pc-windows-msvc build --release -p figcraft --locked

--release otimiza o binário; -p figcraft seleciona o pacote principal; --locked exige respeitar Cargo.lock. Se o lockfile não corresponder ao manifesto, investigue antes de removê-lo ou atualizar dependências.

4.3. Como reconhecer o sucesso

Finished `release` profile [optimized] target(s) in ...

Depois, procure target\release\figcraft.exe. O nome e o local devem ser confirmados na saída real do Cargo e nos metadados do pacote; não presuma sucesso só porque apareceram mensagens Compiling ....

4.4. Recompilações

Após editar o código, rode novamente wmk-compilar.cmd. O Cargo reutiliza artefatos intermediários. Evite cargo clean por padrão: ele elimina o cache de compilação e pode exigir muito tempo e espaço para reconstruir tudo.

4.5. Compilar manualmente e acompanhar o progresso no terminal

Abra o Prompt de Comando (CMD) do Windows, e mantenha essa janela aberta durante o processo. Execute os comandos abaixo nesta ordem:

cd /d D:\Ferramentas\figcraft
wmk-compilar.cmd

O script ativa o ambiente MSVC e executa o Cargo em primeiro plano. Você verá as linhas Compiling ..., avisos, erros e, quando terminar com sucesso, Finished `release` profile .... Não feche o terminal enquanto estiver compilando.

Comando direto (sem script)

cd /d D:\Ferramentas\figcraft
call "D:\one\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"
cargo +1.95.0-x86_64-pc-windows-msvc build --release -p figcraft --locked

Esses caminhos de exemplo são específicos desta instalação. Para ver mais detalhes, substitua a última linha por:

cargo +1.95.0-x86_64-pc-windows-msvc build --release -p figcraft --locked -vv

-vv aumenta a verbosidade, mas não cria uma barra de porcentagem e pode continuar sem imprimir mensagens enquanto um módulo grande é otimizado.

Registrar o resultado em arquivo

Opcional: no PowerShell, após ativar o ambiente MSVC usando o script acima ou um Developer Command Prompt, execute:

cd D:\Ferramentas\figcraft
cargo +1.95.0-x86_64-pc-windows-msvc build --release -p figcraft --locked -vv 2>&1 | Tee-Object -FilePath .\wmk-build.log

Esse comando grava as mensagens e as mostra na tela. Atenção: o pipeline do PowerShell pode mascarar o código de saída do Cargo em algumas versões; confirme também a mensagem final e o executável.

Consultar atividade de CPU sem interromper a compilação

Em outra janela do PowerShell:

Get-Process cargo,rustc -ErrorAction SilentlyContinue | Select-Object ProcessName,Id,CPU,WorkingSet

O campo CPU é acumulado. Compare duas leituras: se aumentar, o processo está usando CPU. Também há um diagnóstico local no arquivo wmk-diagnostico-build.ps1, que mede duas amostras e consulta memória, discos e executável.

Como cancelar sem apagar o cache

Com o terminal da compilação em primeiro plano, pressione Ctrl+C uma vez e aguarde o encerramento. Ao iniciar novamente, o Cargo normalmente reutiliza dependências e artefatos concluídos. Não use cargo clean apenas para reiniciar.

Checar resultado

if exist D:\Ferramentas\figcraft\target\release\figcraft.exe (echo COMPILADO) else (echo AINDA AUSENTE)
Histórico real: a compilação demorada iniciada em 07/11/2026 foi interrompida manualmente a pedido do usuário, sem limpar target. Até esse cancelamento, o executável final não havia sido encontrado. Uma nova execução precisa ser validada independentemente.

5. Validar a compilação

cd /d D:\Ferramentas\figcraft
if exist target\release\figcraft.exe (echo EXE ENCONTRADO) else (echo EXE AUSENTE)
dir target\release\figcraft.exe
cargo +1.95.0-x86_64-pc-windows-msvc test --workspace --locked

O comando de testes é uma proposta de validação; não foi executado e validado como aprovado nesta sessão. Alguns testes podem exigir recursos adicionais. Execute primeiro o binário em ambiente de desenvolvimento e confira abertura, renderização, fontes, importação/exportação, gravação de arquivos e fechamento sem erros. Registre versão do Rust, hash Git, sistema operacional e logs de erros.

Para depuração, utilize cargo +1.95.0-x86_64-pc-windows-msvc build -p figcraft --locked (sem --release) e procure o executável em target\debug. A versão debug pode ocupar espaço adicional.

6. Problemas conhecidos e diagnóstico

SintomaCausa provável / ação
link.exe not found ou erro MSVCInstalar workload C++ e executar vcvars64.bat antes do Cargo.
rustc version ... is not supportedUsar Rust 1.95.0 MSVC ou a versão requerida pelo manifesto/lockfile.
Disco cheio durante a compilaçãoVerificar espaço em C: (caches do Rustup/Cargo) e D: (código e target); não apagar projetos. A primeira tentativa foi interrompida quando D: tinha menos de 2 GB livres.
craft-fonts fonts/manifest.txt skippedA compilação observada não encontrou CRAFT_FONTS_DIR=D:\Ferramentas\figcraft\../craft-fonts e seu fonts/manifest.txt. Investigar instruções oficiais do repositório e impacto na aplicação. Não criar um manifesto fictício.
patch ... was not used in the crate graphAvisos de patches egui não utilizados. Em geral não interrompem o build; revisar compatibilidade de versões se necessário.
Cargo demora sem imprimir novas linhasInspecionar processos cargo.exe, rustc.exe, CPU, memória e espaço. Linkedição/otimização release podem demorar.
Dependências Git ou crates.io indisponíveisVerificar rede, proxy, certificados e acesso a GitHub/crates.io. Não editar Cargo.lock sem necessidade.
Binário abre sem recursos/fontesVerificar arquivos auxiliares, fontes e empacotamento; um executável criado não garante que a distribuição esteja completa.

7. Preparar documentação e publicação no GitHub

Antes de publicar, revisar scripts para remover caminhos específicos desta máquina. Recomenda-se usar vswhere ou instruir o desenvolvedor a executar um Developer Command Prompt apropriado. Adicionar ao README principal um link relativo para este arquivo:

[Manual de compilação Windows (PT-BR)](manuais/manual-compilacao-windows.html)

Publicar somente após revisar mudanças e testes:

git status
git add manuais/manual-compilacao-windows.html
git commit -m "docs: adiciona manual de compilacao Windows em pt-BR"
git push origin NOME-DA-BRANCH
Importante: criar este manual no diretório local não equivale a publicar no GitHub. O git push só deve ser feito após conferir branch, acesso, conteúdo e autorização de publicação. Não foi executado automaticamente por este documento.

8. Checklist para outros desenvolvedores

  • ☐ Windows x64, Git e internet disponíveis.
  • ☐ Visual Studio C++ e Windows SDK instalados.
  • ☐ Rust 1.95.0 MSVC instalado.
  • ☐ cl e link encontrados no terminal.
  • ☐ Espaço livre suficiente em discos de projeto e cache.
  • ☐ Fork clonado e hash do commit registrado.
  • ☐ cargo build --release -p figcraft --locked finalizado com sucesso.
  • ☐ Executável produzido e aberto.
  • ☐ Recursos/fontes e testes funcionais verificados.
  • ☐ Pacote de distribuição revisado e documentado.

Este manual é um guia reproduzível de ambiente e compilação, não uma certificação de build concluído. Atualize-o sempre que a versão do projeto, dependências ou scripts mudarem.
