WMK App Bridge v0.1

Como exportar .wmk para React e TypeScript com vínculos de eventos reais

Walney Moreira Klein — walneyk@hotmail.com

Central de manuais · Laboratório 02

O que construímos

O exportador externo lê o document.json de um .wmk real, detecta Frames principais, consulta um contrato de eventos e gera um manifesto versionado com os IDs e ações. Em seguida prepara um projeto React + TypeScript + Vite. O arquivo original não é alterado.

Este é um primeiro passo para o menu de exportação nativo do WMK Studio. O executável ainda não foi modificado.

Como testar

cd D:\Ferramentas\figcraft
wmk-exportar-react.cmd "laboratorios\wmk-design-to-app\ridgeline-web-poc\ridgeline-laboratorio.wmk" "D:\Projetos\wmk-teste" "tools\wmk-app-bridge\examples\ridgeline.bindings.json"
cd D:\Projetos\wmk-teste
npm install
npm run build
npm run dev

Use uma pasta de saída nova/vazia. O exemplo de bindings referencia IDs específicos do Ridgeline; outros documentos precisam de contratos próprios.

Formato do manifesto

CampoFunção
schemaVersionVersão wmk-app-bridge/v1
sourceFormat/sourceVersionOrigem do documento
screensIDs, nomes e dimensões dos Frames
bindingsIDs de nó, role input/button e ação screen.navigate
dataModelsEntidades e campos do CRUD local demonstrativo
diagnosticsLimitações da exportação

O contrato é externo. O próprio WMK Studio ainda não salva nem edita esses vínculos.

Resultados reais

O conversor processou 349 nós, três telas e cinco vínculos. O validador rejeitou seis entradas inválidas (ID inexistente, destino inválido, ação não autorizada, schema incompatível, tipo de campo inválido e duplicidade). A verificação TypeScript e o build Vite passaram: 33 módulos transformados.

O npm informou que bloqueou um postinstall do esbuild, mas a compilação concluiu. Ainda não foi feita comparação visual nem teste end-to-end das ações no navegador.

Funcionalidades e pendências

Já existe geração de manifesto, projeto React compilável e vínculos declarativos. A aplicação possui exemplo de inclusão, pesquisa e exclusão em localStorage; não há persistência em servidor, edição completa, autenticação ou backend SQLite. O visual ainda é aproximado para redes vetoriais, efeitos e Auto Layout. Não existe herança de métodos VFP.

Próximo passo recomendado: painel Behavior no WMK Studio para editar os vínculos por componente, salvar lado a lado com o arquivo .wmk e chamar o gerador por menu. Em seguida integrar SVG nativo, Code Connect e geração de APIs.
