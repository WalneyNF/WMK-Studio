Do Design ao Aplicativo com IA

Como aproveitar o Dev Mode, Code Connect e MCP do WMK Studio e gerar aplicações conforme uma stack escolhida

Academia WMK Studio • Walney Moreira Klein — walneyk@hotmail.com

Índice de manuais · Raio X · Central RAD

1. A resposta objetiva

O WMK Studio não é apenas um desenhador de imagens: possui editor visual, componentes, Auto Layout, Dev Mode, inspetor, gerador de trechos de código e Code Connect. Não é ainda um gerador integrado de aplicativos comerciais completos. O backend, o banco, a segurança, as rotas e as regras de negócio exigem desenvolvimento adicional.

3. Fluxo ideal da WMK Software Factory

Escolher template + suas classes visuais + tema
  ↓
Editar tela .wmk (componentes, propriedades e Auto Layout)
  ↓
Mapear componentes visuais para componentes reais do framework
  ↓
Escolher stack e restrições do projeto
  ↓
Extrair árvore estruturada por MCP/Dev Mode
  ↓
IA gera plano de implementação e código
  ↓
Gerador determinístico cria esqueleto + componentes aprovados
  ↓
IA implementa rotas, validação, serviços, banco e testes
  ↓
Build/testes reais → prévia → revisão → entrega do projeto

A etapa visual não determina sozinha tabelas de dados, permissões de usuário, regras comerciais nem APIs: essas informações entram em um contrato funcional adicional.

4. Contratos para gerar um projeto de forma repetível

{
 "schemaVersion": "wmk-app-project-v1",
 "template": "wmk-cadastro-v2",
 "theme": "wmk-dark",
 "target": {
   "ui": "react",
   "language": "typescript",
   "css": "tailwind",
   "api": "node-fastify",
   "database": "sqlite"
 },
 "entity": "clientes",
 "fields": [
   {"name": "id", "type": "uuid", "required": true},
   {"name": "nome", "type": "string", "required": true},
   {"name": "email", "type": "email"}
 ],
 "features": ["list", "search", "create", "edit", "delete"]
}

O contrato é uma proposta nova, não um arquivo suportado pelo programa atual. O sistema precisa validar referências de classes, schema, componentes, comandos e versão do template.

5. Por que usar Code Connect?

Se o desenho contém uma instância visual de WMKTextBox, a fábrica não precisa convertê-la em HTML genérico. Ela pode gerar um <WMKTextBox ... /> real de uma biblioteca React, desde que o Code Connect tenha mapeamento para o componente e suas propriedades. Esse é o caminho para manter o estilo e a lógica da classe-base em todos os sistemas.

Os comportamentos devem ser especificados separadamente: onSearch, onSelect, required, dataField, mask, validação e permissões. Um botão desenhado não contém automaticamente código de gravação.

7. Plano de implementação por fatias

  1. P0 — Inspeção: compilar figcraft-cli, usar MCP para extrair uma tela e gerar código existente; registrar diferenças visuais.
  2. P1 — Code Connect WMK: associar WMKButton, WMKLabel, WMKTextBox a componentes React reais. Criar testes de mapeamento.
  3. P2 — Template CRUD: frmConsulta + frmCadastro, entidade Cliente e contrato de dados validado.
  4. P3 — App gerado sem IA: gerar esqueleto React+Fastify+SQLite por templates determinísticos; testar build, persistência e operações CRUD.
  5. P4 — IA local: Ollama recebe contrato de design e regras; gera plano e código somente em workspace isolado, sujeito a validação.
  6. P5 — Provedores: Groq e outros com timeout, rate limit, permissões e controle de custo.
  7. P6 — Novas stacks: validar React Native/Flutter e outros alvos um de cada vez.

8. Cuidados de segurança e engenharia

  • Não executar comandos shell fornecidos livremente por modelos; allowlist e isolamento por workspace.
  • Credenciais em variáveis de ambiente/gerenciador seguro, nunca incorporadas ao repositório de design.
  • Autenticação, autorização, validação server-side, migrações, logs e testes são exigências distintas da aparência visual.
  • Antes de declarar um aplicativo concluído: testes unitários, integração da API, persistência, build, análise de dependências e revisão visual.
  • Preservar bibliotecas base, atualizar por versão e respeitar overrides.

9. Ferramentas do mercado que demonstram viabilidade

Figma Code Connect documenta vínculo entre design e código de componentes. Builder.io e Locofy oferecem fluxos de design-para-código e integração de bibliotecas existentes. São referências para estudar padrões de arquitetura, não dependências obrigatórias do WMK Studio.
