Central de manuais · Visão do gerador de aplicativos

1. Objetivo

Avaliar se as informações salvas em um documento do editor permitem reconstruir uma aplicação em outra tecnologia. O experimento usa a cópia do arquivo examples/ridgeline-app.figcraft, chamada ridgeline-laboratorio.wmk. O conteúdo original não foi modificado e o metadado interno format=figcraft foi mantido para compatibilidade. O arquivo é um exemplo real do repositório, e não um design novo criado manualmente nesta sessão.

O formato é um contêiner ZIP que contém document.json, miniatura e possivelmente imagens/referências. O JSON preserva nome, páginas, árvore de nós, propriedades, estilos, coleções de variáveis e outros metadados. Isso é mais rico que uma imagem PNG.

5. O que falta para gerar um aplicativo real

  1. Obter SVG/PNG das formas complexas com a engine Rust, não substituí-las por blocos genéricos.
  2. Traduzir Auto Layout, posição, recorte, estilos e fontes para CSS responsivo.
  3. Usar Code Connect para mapear componentes WMK às implementações reais React/TypeScript.
  4. Definir contratos de eventos (Click, Change, Submit) e rotas de navegação.
  5. Definir dados e comportamento: entidades, validação, APIs, autenticação e persistência.
  6. Gerar estrutura React/Vite, backend e banco, com testes executáveis e build.
  7. Conectar IA para propor as regras e o conteúdo, sempre validando contra presets aprovados.

6. Testes realizados

Validação do ZIP-fonte, estrutura JSON com 349 nós e três Frames, verificação sintática JavaScript com node --check app.js e teste de integridade do ZIP do laboratório. Não houve teste de renderização visual automatizado no navegador nem compilação React/TypeScript, porque esta primeira versão é JavaScript sem dependências.

O arquivo original da amostra e a release pública do WMK Studio não foram alterados. Este experimento é separado do executável principal.

7. Próxima prova de conceito

Usar o mesmo documento e gerar um projeto React + TypeScript com componentes reais, aproveitando crates/engine/src/dev/codegen.rs, component_codegen.rs e code_connect.rs. Conferir o visual das telas contra o renderer Rust e adicionar comportamento para pelo menos um botão, uma entrada de texto e uma navegação. Só então partir para CRUD com Fastify + SQLite.
