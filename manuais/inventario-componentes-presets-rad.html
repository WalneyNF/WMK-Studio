1. Resultado verificado no código

Os tipos básicos no enum NodeKind de crates/doc/src/node.rs são Page, Frame, Group, Section, Rectangle, Ellipse, Polygon, Star, Line, Vector, Text, BooleanOp, Component, ComponentSet, Instance e Slice.

Isso é a lista das categorias fundamentais de nós do documento, não uma contagem de widgets funcionais prontos. Um botão, input ou grid visual pode ser montado a partir de nós existentes e salvo como componente.

O arquivo crates/engine/src/cmd/component.rs registra component.create, instance.create, instance.swap, component.detach, component.resetInstance, component.pushChanges e propriedades de componentes.

2. Como criar e derivar componentes hoje

  1. Desenhe uma peça com Frame, Text e outras camadas.
  2. Selecione a peça e use Criar componente (Ctrl+Alt+K no Windows, conforme atalho documentado).
  3. Insira instâncias do componente usando o painel Recursos ou a função de instância.
  4. Edite overrides permitidos, como texto e preenchimento, sem desconectar a instância.
  5. Crie variantes no conjunto de componentes para estados/tamanhos; use propriedades de variante, booleano, texto ou troca de instância.
  6. Publique os componentes como biblioteca local; vincule a outros documentos, com atualização e preservação de overrides.

Derivação real: composição de componentes aninhados, instâncias, variantes e overrides. Limitação: isso não configura herança executável de métodos do VFP (extends/super) por si só.

Documentação original: docs/components-parity.md, linhas 11–33 para componentes/instâncias e 51–57 para bibliotecas.

3. Preset RAD não é apenas uma imagem

O preset precisa apontar para componentes reais e expor identidade, versão, tema, campos, layouts, ações e regras de composição. O exemplo wmk.crud.clientes.v1 lista os campos de clientes e a árvore de elementos, mas não tenta escrever diretamente o documento .wmk.

Campo do presetFunção
id / version / categoryIdentificar e versionar, escolher pela categoria do projeto
baseTemplateIndicar o formulário-base de referência
themeEvitar que a IA mude livremente a identidade visual
entity.fieldsDefinir os dados que o CRUD manipula
compositionDescrever a árvore de componentes e contêineres
rulesBloquear componentes ou hierarquias não autorizados
allowedStacksSeparar o desenho do alvo de geração de código

4. Hierarquia obrigatória do CRUD de clientes

WMKForm
├── header → WMKHeading
├── content
│   ├── WMKFieldGroup
│   │   ├── WMKInput Nome
│   │   ├── WMKInput E-mail
│   │   └── WMKSelect Situação
│   └── WMKDataGrid Clientes
└── actions → WMKActionBar
    ├── WMKButton Novo
    ├── WMKButton Salvar
    ├── WMKButton Excluir
    └── WMKButton Cancelar

O motor RAD não deve aceitar botão fora de um slot permitido nem campo fora de um grupo válido. O catálogo pode também limitar quantidade de filhos, propriedades, estados e ações.

5. O primeiro gerador com IA

  1. Usuário escolhe o preset por nome ou informa “use wmk.crud.clientes.v1”.
  2. O gerador carrega o JSON, consulta a biblioteca, valida IDs e dependências.
  3. O modelo Ollama/Groq pode propor somente as diferenças: entidade, campos, títulos e regras.
  4. O validador determina hierarquia e ações; caso o modelo invente componente, a operação falha com diagnóstico.
  5. Um executor futuro traduz a estrutura validada em comandos reais do WMK Studio (CLI/MCP/engine) e cria o documento editável.
  6. Uma fase posterior usa geradores por stack para produzir frontend, backend e banco de dados, submetendo tudo a testes.

O modelo não deve executar código livremente nem sobrescrever o preset oficial. Templates novos gerados pela IA entram como rascunhos e dependem de aprovação.

6. Arquivos criados neste estudo

wmk-rad-presets/registry.json — oito tipos de componente propostos, com slots permitidos.

wmk-rad-presets/examples/crud-clientes-v1.json — primeira composição de um CRUD, com campos e ações declarativas.

O catálogo e o preset passaram por validação estrutural em script de auditoria (IDs, slots, quantidade de filhos e ações). Isso não significa que já são importáveis no WMK Studio: faltam parser, UI, integração com biblioteca e executor de geração no aplicativo.
