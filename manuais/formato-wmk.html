WMK Studio: formato nativo .wmk

Guia de alteração de extensão para usuários e desenvolvedores.

Walney Moreira Klein — walneyk@hotmail.com

1. O que significa .wmk?

.wmk é a nova extensão padrão dos documentos criados pelo WMK Studio. Ela identifica os arquivos do projeto, não um novo formato binário incompatível. O conteúdo mantém o arquivo nativo de design herdado do FigCraft, com o formato interno e as estruturas originais preservadas nesta etapa.

2. Compatibilidade

ExtensãoComportamento esperado após recompilar
.wmkAbrir e salvar como formato padrão WMK Studio
.figcraftAbrir e manter compatibilidade com projetos legados; Salvar Como permite escolher o tipo antigo
.figExportação/importação experimental com suas limitações próprias; não é o formato WMK
Não renomeie nem apague os projetos antigos em massa. Faça backup, abra uma cópia e use Salvar Como para gerar .wmk. Para um documento já aberto como .figcraft, o comando Salvar pode conservar seu nome antigo; use Salvar Como para migrar.

3. Utilização

  1. Abra o WMK Studio recompilado.
  2. Crie um novo arquivo de design.
  3. Use Arquivo → Salvar Como e confirme que a sugestão termina em .wmk.
  4. Salve meu-projeto.wmk.
  5. Feche e abra o arquivo salvo; confira as camadas, fontes, formas, cores e imagens.
  6. Teste abrir um documento .figcraft existente sem substituí-lo.

4. Implementação

Alterados padrões de salvamento na interface e no motor, reconhecimento na importação e abertura, filtros do Windows e identificação de miniaturas. A extensão antiga continua permitida. O identificador interno FORMAT = "figcraft" foi intencionalmente preservado para manter a compatibilidade do conteúdo.

O sistema de recuperação automática usa sua extensão interna legada por enquanto, para preservar a recuperação de sessões antigas; isso não impede o formato de documento .wmk.

5. Como validar a versão nova

cd /d D:\Ferramentas\figcraft
wmk-compilar.cmd

Depois da compilação, confirme a mensagem Finished release profile, execute o aplicativo novo e realize os testes do item 3. O executável antigo não ganha suporte a .wmk apenas por alterar o código-fonte: é necessário recompilar.

6. Situação

Os arquivos de código foram alterados localmente. A confirmação final depende da compilação/testes do novo build e de abrir/salvar documentos reais. Não presuma que as alterações já estejam no GitHub.
